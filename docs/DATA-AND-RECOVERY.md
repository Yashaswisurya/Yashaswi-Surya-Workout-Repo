Import reports list new, duplicate, conflicting, missing and skipped records and transformations. Review the original file before any mapping. Native export includes goals and audit data, but imports add only new active daily records; restore goals explicitly in Goals. Recover deleted entries through Trash or whole-Sheet recovery, not by auto-restoring an import.

## Relational Google Sheets schema

Column order is defined exactly in `TABLES` in `apps-script/Server.js`. Empty numeric cells mean unknown, not zero. Numeric zero stays zero. Dates are ISO `YYYY-MM-DD`, timestamps UTC ISO strings. Main records use stable UUIDs and increasing versions; each child has a stable ID and foreign key. Child rows also store createdAt/updatedAt ISO timestamps and are updated as part of the parent log revision; the audit log records each parent mutation. Forensics and field-by-field revision history rely on Sheets version history and JSON backups, not a claimed full audit diff.

All child tables include createdAt and updatedAt ISO timestamps in addition to the columns above. All fitness children are normalized rows, not nested objects packed into a daily cell. Full JSON backup is deliberately nested for portability. `shared/domain.js` validates frontend and backend data. Backend validates again, checks owner identity on every API operation and uses a script lock for writes and consistent reads. Original IDs are preserved when editing. A stale expectedVersion is rejected. Network failure leaves the editor open; an unchanged retry uses the same request ID to avoid duplicates. After a successful save followed by reload failure, reload before another edit.

## Calculations

All dashboard period calculations use the global date range; explicitly labeled current-week intentions and current/best streaks use the relevant full dataset. Dates follow Asia/Kolkata. Average calories, protein, water and sleep exclude missing values. Latest weight is latest **within the selected range**, not a profile estimate. Weight change requires two recorded weights. Weekly check-in completion counts rest/recovery as valid; future days are not a failure. Workout frequency counts documented sessions, not a checked checkbox without session details. Daily quick flags can record completed activity when details are unknown.

Volume requires sets AND reps AND kg; missing sets are never inferred. Badminton win rate uses only sessions with explicit wins AND losses, so partially documented session results cannot bias its denominator. Recorded wins are summed separately. A missing loss count is never assumed to be zero. Aggregated sessions do not establish match sequence, so winning streak is unavailable. Meal nutrients do not automatically overwrite separately entered daily totals. Supplement follow-through is taken/entered doses, not assumed daily adherence. Gaps in charts are not interpolated measurements; line segments connect known points only.

## Backups

- Settings → Export full JSON includes all logs including soft-deleted records, nested children, goals and (in cloud mode) audit entries. Keep it in private storage.
- CSV export is a spreadsheet-safe daily summary only; it is **not a full backup** of exercises/meals.
- Settings → Create private Drive backup is opt-in and available only in cloud mode. No automatic schedule is claimed.
- Before imports or upgrades, use File → Make a copy on the private Sheet, plus JSON export. Keep copies restricted. Do not publish a backup link or commit personal data to GitHub.

## Recovery

1. For a mistaken delete, use Settings → Recoverable trash → Restore. If a different active log exists for that date, review both before choosing which to keep. Nothing is silently merged.
2. For a mistaken edit, obtain an earlier JSON backup and compare values. The importer does not overwrite existing records: use History to manually restore reviewed fields while retaining their source notes, or restore the whole Sheet version below.
3. For corruption or a failed rollback, stop editing. Make a forensic copy of the current Sheet. In the original Sheet use File → Version history → See version history, select the correct version and restore. This restores related tables together; avoid restoring just DailyLogs without children. Then reopen /exec, reload, and verify parent and child rows.
4. For a fresh database restore, use a new private Sheet/Apps Script deployment and initialize. Import the JSON with preview; active records are added, deleted records remain in the backup and are not resurrected automatically. Reconfirm goals. To retain deleted rows and full audit history exactly, restore a complete Sheet copy/version instead of JSON import.
5. Keep original backup files unchanged until the restored dataset has been verified on two devices.

No Google-hosted recovery or permission check has been executed without your account authorization.
